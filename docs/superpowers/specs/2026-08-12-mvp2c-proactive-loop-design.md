# MVP 2C Codex 主动意图循环设计

任务：`20260812-006`

## 决策

把“主动”落实在 Codex 每次正常工程请求的前台启动循环中，而非启动后台守护进程。项目 Skill 在读取 handoff、完成 `repo-health`、必要时初始化本地控制库后，自动运行一次：

```text
scripts/team-control process-pending-intents --limit 10
```

它只会在以下条件全部满足时运行：请求不是严格只读、不是仅查看/打开工作台、仓库健康、控制库已存在。队列返回单条 `REJECTED` 或 `BLOCKED` 时，Codex 记录并报告后继续当前请求；命令本身非零时，停止后续写入并只报告控制面问题。

## 不变量

- 处理规则完全复用 MVP 2B：每条仍重新核验 HEAD、状态、审批和 prepared-operation。
- 每次启动至多 10 条；不启用 timer、线程、daemon、webhook 或网络监听。
- 严格只读与工作台查看不初始化数据库、不运行队列、不产生任何写入。
- 浏览器始终只有意图提交权；不会新增处理端点、按钮或自动 POST。
- 队列不包含 Git、merge、push、发布、审批 nonce 消费或权限扩大。

## 验证

测试必须锁定 Skill 文字合同：触发条件、固定上限、非零退出停止写入，以及严格只读/工作台豁免。用户手册说明默认行为和停止条件。最终 Claude 审阅只覆盖本次小范围合同变更。
