## 这份记录写什么

本仓库没有 v1.3 原文，不从仓库外的材料重建旧稿。下面五条是获准公开的 v1.4 差分。

若阅读到「正在外部应用」，以公开状态码 `role_contracts_applied_and_readback_verified` 为准。状态补充不修订下面五条。静态回读没有把 Bot 指令变成安全沙箱，没有把单入口改成串行，没有恢复固定两确认，没有发布评分或 skill，也没有把未实测阈值写成政策。

## 1. 不固定两确认

已经覆盖的可逆工作，不做机械两确认。范围、权限、驻留、费用上限或不可逆动作发生实质变化时，再确认。技术验收、用户接受、动作授权分别记录。

## 2. 不把单入口等同串行

默认使用一个统一用户入口。入口核对、汇总并编排。计划可以包含并行工作。单入口不是串行执行的同义词。并行工作不构成第二派单。

## 3. 不把 Bot 等同安全域

职责、Bot、工具、模型、身份、安全边界保持为不同对象，不一一对应，不排成笛卡尔积。实际 Bot 指令不自动等同角色安全沙箱。更新 description 或回读 profile，都不改变这条边界。

## 4. 延后全量入口、评分和 skill 发布

职责地图保留 14 个职责。首轮每个任务只激活协调入口、一个执行职责和独立验收。全量入口、评分和 skill 发布都延后。

skill 若将来推进，只走：候选、多场景测试、独立复验、授权批准、版本发布后的观察或回滚。skill 不自行改变权限、预算或隐私。

## 5. 不用未实测阈值作政策

没有实测支持的数值阈值不写成政策。模板中的预算、费用上限和试点口径保持待填。13 项静态配置核验是描述与 profile 的核对计数，不是数值政策门槛。

- 项目经理和路由建议不能第二派单。

- 不读取、不迁移真实个人数据。

- 外发默认是用户审阅草稿。工作流完成不是发送许可。
- 未实现的控制不写成已有技术保障。
