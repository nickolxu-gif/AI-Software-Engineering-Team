# 专岗协作组织：实施基线

基线日期：2026-11-08（北京时间 UTC+8）

## 1. 阶段、状态与组织原则

已从持续设计讨论转入分批实施、真实运行验证、后续迭代。实施起步不要求先补齐全部设计；不能把“开始实施”推导为私人资料访问、外部发送、付费升级或敏感能力的概括许可。

本文件区分：**已选分工**、**设岗倾向**、**候选职责/配置**、**未定细节**、**能力未验**。各项只有拿到具体实施及回读证据，才能另标“已配置”；只有实际运行证据才能标相应功能“已验证”。

- 历史的“6入口＋14逻辑岗”是旧配置合同，不是目标组织结论。已选独立专岗应有真实长期机器人、独立职责、工作台与方法经验，不由少数机器人轮换角色替代。
- 三层是幕僚判断、专业执行、个人生活与知识的职责/访问域，不是固定审批链，也不是技术隔离证明。研究、信息收集等可跨层供给，不强制定层。
- 岗位稳定，工具可替换，模型依任务质量、预算、权限及隐私证据选择；不建立岗位×工具×模型的笛卡尔积机器人。
- 岗位长期存在与本任务是否参与是两件事；不全岗串行、不一工作步骤一机器人、不以最终人数为目标。
- 合理的交叉提问与自主批判保留；独立审查、专业验收不能由作者自查代替。
- 全图分批落地；首批小范围运行不是缩减组织，也不让候选自动转成定案。

### 2.1 研究—战略—规划的反馈

1. 研究可给有条件行动建议，分清证据支持和价值假设；战略结合用户目标及其他约束比较。
2. 用户选方向后，战略交“选定方向＋选择依据＋关键假设/约束”，规划再细化工作与验收。
3. 规划发现方向可能不可行或明显超投入边界，保留原计划版，交战略重评方向可行性；主协调者汇总差异和待决策。不强制先找方向内调整，不自动整单作废。
4. 反对者可给反例/替代思路解释根本问题，完整方向方案仍由战略维护；修订后复核价值前提，不替方案审查核需求覆盖/依赖/实施可行性。
5. 维护者记录采纳/部分采纳/不采纳及依据，部分采纳保留未解项；“已回应”不等于“已解决”。
6. 巨大分歧沿既定讨论条件处理：目标/价值根本冲突；足以改方向的关键事实或假设争议；投入、隐私或不可逆风险显著不同而既定标准不足；用户主动要求。讨论不等于多数票决策，也不自动授权联络/建群。

尚待细化而非阻止首批：确认目标与需求/战略版的关联；同时涉及需求理解、方向前提和实施计划的混合问题如何分流及凭何证据收口。不得为此新增每单强制门禁。

## 3. 软件、建模和专业执行

| 已选长期专岗 | 职责与交接 | 关键边界 |
|---|---|---|
| 领域建模 | 跨系统概念、业务规则、关系及领域模型版本；规则缺口附影响交需求岗统一问用户 | 不自行补业务规则；与需求各维护版本，区别于技术存储/接口设计 |
| 软件架构 | 模块边界、接口、数据设计与关键技术/运行约束；接业务模型与确认需求 | 不替规划决定业务目标；接运维早期约束 |
| 交互与界面设计（一个岗） | 操作流程、状态、原型、视觉，按版本交开发 | 表达/原型不等于实现正确 |
| 代码开发 | 架构及工作包内自主实现、自测，交代码/差异/实现证据 | 模块、接口、数据模型、关键运行约束变化先向架构提变更；自测非独立验收 |
| 软件测试 | 测试方案、跨模块验证、回归、缺陷复现；记录版本、环境、用例及实际结果 | 不合并代码验收，不替作者取得独立通过 |
| 工程化运维 | 架构时提部署、可观测性、备份恢复约束；开发中核对；交付后部署、监控、备份恢复和故障处理 | 实施/修复不等于独立运行验收，职责非一次交付结束 |
| 产品外观设计＋三维建模（同一岗） | 参考图/需求沟通形成可编辑模型，重点展示，按约定提供工程使用模型 | 未知尺寸/内部结构/材料标假设；展示或可编辑不等于工程合格 |
| 工程设计 | 结构、材料、工艺约束，方案/计算/仿真、假设与证据 | 仿真无错非实物安全证明；不独立验自己产物 |

软件线：需求/领域→架构；界面与架构→开发；运维约束提前介入；测试反馈对应维护者；代码与运行可靠性分别交验。必要工作可并行，不是单向瀑布。

三维线：外观与工程在已确认关键外观、功能、安全和成本边界内协商并记录版本；越界由协调者汇总选项交用户。计算/仿真保留模型、几何/材料来源、载荷/边界条件、假设、方法和限制；需实物验证而未做的列未验。软件测试、渲染美观不能代工程核查。

安全责任分布于需求用途/边界、架构接口权限数据设计、开发实现、运维运行配置与凭据生命周期、相关独立验收证据；细分及能力未验，不因原则自动建立安全岗。

素材规格、小样、返工交接、版权授权、真实人物声音肖像及风格一致性具体检查仍待定/待验；不是默认素材访问或公开发布许可。

## 5. 阅读、知识与信息研究

### 5.1 已选阅读与知识分析

- 阅读整理：保真、出处、提取、获准上下文回查，区分作者内容/用户批注/机器人解释；维护整理产物及修订，不静默改原件。
- 知识分析：长期连接概念、观点、关联、分歧、空白，区分概念/前提/证据/情境；暂定解释、反例和待验证项。材料没提、证据不足、信息冲突分别标识，不推定用户理解有缺陷，不替个人复盘推断动机。
- 小批迭代先约首批/检查条件/获准总范围/恢复，首批通过可继续范围内后续，不逐批重批、不无限推广。分析疑问交整理维护者处理，记录建议采纳及新版本；不能免去必要独立验收。

### 5.2 信息收集与专题研究：分别设岗倾向，非最终设立结论

- 信息收集按确认主题筛选、去重、保留出处上下文、保真摘要和来源不确定性；转述不是核实，证据比较和结论交研究。
- 专题研究围绕明确问题组织证据、比较解释、给依据/不确定性/适用范围及有条件建议。关键证据不足影响结论，先交发现、缺口、补查建议，用户决定继续投入，不自行扩研究。
- 研究与知识分析按工作目的划界，非公私来源；按授权复用，各自维护不覆盖。通用研究整合问题/证据，领域岗维护专业判断，争议不整成定论，整合不扩权限/另建派单链。
- 知识内容验收核引用、证据链和结论外推；领域判断按需补独立核查，缺能力标未验，领域提供者自查非独立通过。未选新研究审查岗。
- 收集筛选去重细则、触发频率、交接版本时效和专业核查资源未定；不因此默认建例程，也不把每项任务再确认一遍。

### 5.3 知识库维护与维护验收：候选配置，部分责任规则已选

既有知识库及维护自动化应在现状上衔接完善，而非另起一库；真实规则和成熟性未核实。维护责任与执行工具的最终绑定未定，不据此创建独立维护机器人或替换现有工具。

已选维护责任：获准格式/元数据/分类归档/版本关联/落库，不改原意；统一保管**获准入库**原始资料/版本，未获入库留原处。保管非全员可读；原音频、原邮件等与转录摘要分析区分，各专业维护衍生，不覆盖原件。

规则：
- 内容、元数据、引用经核对无实质差异的重复才依明确规则处理并留恢复记录；其他只建议，相似度非重复证明，未知差异也只建议。
- 既定规则覆盖的标签/索引/归档可在获准范围执行并验链接；变分类体系/关联含义/归类歧义先提方案。
- 分批规划约首批/检查条件/总范围/恢复；每批检查结果与任务内恢复证据；重大偏差用户决定。
- 关联入库分有出处关系/分析解释/待验证假设，附依据版本；获准范围既定规则内可入，入库不等于证实。
- 纠错留记录和版本，通知引用维护者评估：仍成立保留、需改更新、未核待复核，非整库失效。明确受影响结论，待复核不得作已核实依据，关键决策/不可逆动作暂停依赖它，未受影响可继续；复核更新证据版本状态，非简单删提示。

专门知识库维护验收先讨论候选、不立即设立：核每批维护/链接/元数据/归档及任务内恢复；知识主张交内容验收、脚本缺陷交代码验收、底层恢复机制交可靠性验收。各维护结论，复用同版本适用证据，不重复建账。

长期规则变更及批量修改须有适用规划/审查覆盖、原件/恢复依据；已有覆盖不机械重审。具体阈值、引用附件支持、并发、恢复和纠错通知能力未验。

| 健康记录＋分析建议（同岗） | 报告/日常指标整理、趋势不确定性、就医问题准备；用户选定睡眠饮食运动目标建议 | 不自行扩症状诊断/治疗调整；健康目标本岗主责，生活岗仅获准协作，不重复跟进或默认共享 |
| 日程与个人待办（单设） | 时间建议、冲突提示、跟进；普通事项约定回顾、重要事项依事先规则提醒 | 用户决定后才写日历，不自行移动；登记非排期许可，不自行延期、不以未回复当完成 |

生活目标变化核记录范围、复盘依据、共享约定影响，仍适用授权保留，新增用途用户确认，旧解释不照搬。结束列拟停活动/可保留资料/可选总结交用户决定；授权到期或撤回不能等决定期间继续，保留非删除。

健康独立核查：现有验收岗核来源/单位/记录保真；解释建议标专业核查缺口，重要医学判断需合格医生意见。不另设健康核查岗，数据核对非医学建议验证。提醒监测、入库共享、能力权限未定。

时间/通信：本人承诺有明确依据且在授权内可登记并引用原文；对方请求、含糊回应、推测只待确认，不自动排期/回复。PM维护项目期限依赖，日程岗维护个人安排，生活岗记实际经历；同事项关联非复制。冲突各说明影响，协调者汇总选项，取舍由用户；个人排期非项目延期或外部承诺改变。重要性规则、提醒回顾时机、完成取消依据、变更同步细则未定。未新增提醒不能推断所有既有例程不存在。

## 7. 专业验收与候选治理

已选专业验收分别长期积累：
- **代码验收**：核成果和测试证据，区别开发自测/软件测试。
- **知识内容验收**：来源、保真、证据链、推断边界，故事逻辑/真实背景；保真检查先归此岗，区分摘录、转录、通信事项方法。发言归属、时间、承诺提取能力不得自称已覆盖；用户意图体验仍用户判断。不另设记录保真岗。
- **多媒体验收**：先一个岗，按媒介内部方法，非工程/运行检查替代。
- **工程验收**：已选独立长期岗，可/不可核查领域按任务细分，能力未验，不宣称万能工程资格。
- **运行可靠性验收**：部署、备份恢复、回滚、故障处理证据，区别运维实施修复。

通用结果验收与专业岗位最终绑定/汇总关系未定，不自动再设总控，也不合并成万能验收岗。可提前指出验收方法问题；不得编写/修改自己独立验的产物再自证。

整体关键通过和可独立交付部分在规划先约，不能事后拆包绕失败。冲突先核版本事实标准，可复验先复验；价值/标准取舍交用户。缺合格独立验收，列未验项、受影响部分不通过，协调者提补核方案供用户决定。某领域通过不抵消另一未通过。

**候选质量与复盘**：重大异常/反复返工/跨岗争议查原因提纠正预防，先分需求、计划、执行、标准、工具条件，证据不足不硬归因；不单方定责、不自行改方法权限标准，普通任务不强制全面复盘。

**候选安全与隐私审查**：先讨论边界/介入再判断细分，非已定创建。拟独立核数据流向、权限、凭据保护、日志泄露、第三方共享，给依据/未验/整改建议；不改自己将审配置、不授权、不代接受风险，不获全私域读取权。已选风险变化介入（新增/改变访问、共享、权限、公开部署等），原遗漏风险不豁免；边界内普通任务执行自查注明未做独立安全审查。违反已确认要求交责任岗整改再复核，未约定风险取舍协调后用户决定。与专业验收各维护结论，同版本适用证据复用，跨领域共同核，不相抵消。

## 8. 统一任务接口、工作台和版本

每单最小记录：问题目标真实确认依据；范围/关键禁区/有影响未知；task_id关联确认版和交接。仅按需要扩展成本、私域、细依赖及检查证据；不编空字段为安全，不每单长表。

每岗独立工作台主入口记录：职责与版、工作包/状态、获准输入引用/产物版/维护者/核查交接、经验回链、正式/试用/停用方法及恢复依据。主协调者只跨岗摘要，不复制全部明细。任务建立、完成、阻塞、影响他岗变更、需协调五类事件同步，最小为任务/工作包版、状态、影响和所需协调，敏感正文不随传；未同步如实标记。自动同步和持久任务源未验，可用明确标记的人工交接起步，不声称消息总线已实现。

唯一维护：需求归需求岗，方向比较归战略，计划归规划，专业成果归作者岗，方案review归方案审查，专业验收归验收岗，依赖进度归PM，获准原件保管归知识库维护职责。维护权非决定权/无限修改权。新改生成新版本，留旧版，按影响更新关联成果；共同编号、摘要、引用及共享连接均不授予访问权。

实施接口建议（不是另加已选强制流程）：
```
task_id / work_package / input_versions / requirement_version
owner_role / authorized_scope / data_boundary
artifact_ref / artifact_version / assumptions / unresolved
check_ref / checked_version / check_scope / conclusion
status / impact / next_owner / handoff_ack_or_unknown
```
建议状态：待界定→可执行→执行中→待核查→已核查/需修正/未验；阻塞/暂停可附在受影响包上。技术核查通过、用户接受、行动许可分开记录，不能用单一“完成”掩盖三者。此状态命名是最小实现建议，可据实际工具调整，不称为已部署状态机。

## 9. 授权、通知、评估和改进

- 用户可直接给专岗明确本岗任务，获准可逆部分登记后开展；跨岗/关键约束不清/超授权交协调者。执行岗不能无限自行跨岗派单。复用有效授权，不机械双重审批；范围、权限、驻留、预算或未覆盖不可逆行为实质变化只处理受影响部分。
- 外部发送/发布、私人资料读取、共享、权限和预算变更仍核具体许可；方法积累不能扩权。职责分离非账号/模型/数据驻留隔离证据。
- 隐私安全/不可逆损失风险先停受影响动作立即通知；另有需用户处理的期限阻塞、超授权重大方向范围成本及时通知。只报告实际可停动作及回执/未知残留，不能以回滚方法声称撤销外部事实。
- 日报只阻塞/风险/待决策，周报取同证据包看履职、价值、用户投入变化；无需重复填报，不为报表制造活动，不默认创建例程。
- 三维分开：岗位履职（质量、证据、边界、交接，由适格独立核查）；任务价值（采用/目标贡献由用户，未显现待观察）；用户投入（必要决定与重复澄清补漏返工分开）。不加权总分，不统一百分比，不用调用量、忙碌、反对量或通过率代质量。
- 经验按任务类型、方法/工具版、质量证据、成本耗时来源、失败条件留存；未知标未知，后续任务修订，不无条件排名，不默认实时用量读取、监控或对照实验。
- 改进：候选说明适用范围/收益/风险/证据→获准任务小范围试用→独立核查→相应委托内发布与登记版本→退化停新版本并核影响回滚。跨岗规则/验收标准/权限变化用户确认。提问顺序、检查清单、排版也只候选，不能删验收、降证据或改含义接口。
- 数据、能力、判断为同一证据包的不同视图：来源时间权限纠错；方法适用失败；当时目标选项依据与事后对照。避免重复污染，以真实复用质量和用户投入改善验证积累，不以机器人数量证明复利。

## 10. 分批落地与首批运行建议

建议先用公开或合成阅读材料运行：真实独立阅读整理→知识分析→独立知识内容验收。所需规划/方案审查也由对应真实专岗完成；不让主协调者临时扮演这些岗而声称独立。简单明确试跑不必调用战略、反对者或所有其他岗位。

先登记哪些是已创建/回读/实际运行/验收/未验证，再逐批扩展已选软件、三维、创作和个人岗位。首批不接私人库、不做对外发送、不改生产资料；在沙箱验证来源、交接、纠错和可恢复性。候选敏感职责不因开始实施自动定案。

建议实现产物：岗位注册表（状态不混用）、岗位合同、工作包/交接模板、验收记录、版本变更记录、非敏感试跑证据与可复现检查。文档/静态检查通过不等于机器人已配置或功能通过。

剩余事项随真实任务细化：混合问题分流与复核收口；领域核查能力；候选岗位配置；创作/健康/日程细则；既有库衔接；权限、预算、工作台同步、引用追踪、保留删除和停止回执的实施证据。其他日常事务按实际需要讨论，不预设财务/购物/旅行等必要岗位。
