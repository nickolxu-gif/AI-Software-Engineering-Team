## 执行七问

### 1. 目的 Why

让没有 CLI/VS Code 使用习惯的 Human 能从 Codex 打开一个可信的本地界面，看清软件 AI 工程团队哪里需要关注、进展到哪里、证据在哪里，同时不产生第二个控制平面。

### 2. 完成态 Done

- 七个只读 API；
- 五类中文视图；
- 一句话启动入口；
- 加载、空态、阻塞、审批、过期、不一致和错误状态；
- 测试、独立 Review、整合后复验和验收工件。

### 3. 证据 Proof

- 验收人：Claude Code 独立审查，Codex 最终复核；
- 自动化证据：完整命令、通过数量和退出码；
- 副作用证据：请求前后数据库 SHA-256、Git status 和 HEAD；
- 展示证据：本地真实数据库的页面截图或结构化检查；
- 位置：`artifacts/dispatches/20260809-001/`。

### 4. 反作弊 Anti

不允许通过以下方式“完成”：

- 用静态假数据冒充真实控制状态；
- 页面写着“只读”但后端仍可写 SQLite、Git 或文件；
- 只实现首页截图，不实现 API、错误态和真实数据流；
- 隐藏过期、漂移、缺失或不一致状态；
- 只跑新增测试而不跑 MVP 0 回归；
- 用同一执行者的自评代替独立 Review；
- 暴露 nonce、凭据、敏感原文或任意文件正文。

### 5. 边界 Bounds

白名单是设计中列出的 Dashboard、只读查询、启动脚本、测试、指南、Skill、handoff 和本任务工件。出现外部访问、写 API、远程绑定、敏感数据、未知 schema、无法证明只读、无关脏改动或三次同类验证失败时停止对应项并保留证据。

### 6. 取舍 Trade

冲突时按以下顺序取舍：只读与安全边界 > 状态真实性 > 可恢复与可测试 > 非技术用户可理解 > 功能完整度 > 视觉精致度 > 开发速度。不得为了页面效果弱化真实性或工程门禁。

### 7. 未知 Unknown

未覆盖情况先记录事实、影响和复现步骤；能隔离时跳过该项继续其他工作，不能隔离或涉及权限/数据风险时转为 `BLOCKED` 并交 Codex/Human 裁决。不得猜测状态、自动修复未知数据库或扩大访问范围。
